# Portfolio — Muffeez Khalid

A Senior Software Engineer portfolio built so that the site itself is the work
sample: static by default, accessible by construction, and measured rather than
asserted. Content covers six years of enterprise MEAN platform work (Angular,
NestJS, PostgreSQL, Kafka, RabbitMQ) and the AI automation layer built on top of
it — agents, RAG, chatbots, n8n and Make.com.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind CSS v4 ·
Motion · three.js + React Three Fiber · Zod · Playwright + axe-core

## Getting started

```bash
npm install
npm run dev          # http://localhost:3000
```

```bash
npm run verify       # typecheck + lint + contrast + e2e
npm run build        # production build
npm run test:e2e     # Playwright (builds and serves automatically)
npm run check:contrast   # WCAG AA check against the real CSS tokens
```

### Environment

| Variable               | Required   | Purpose                                                                |
| ---------------------- | ---------- | ---------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | production | Canonical origin for metadata, sitemap and JSON-LD                     |
| `CONTACT_WEBHOOK_URL`  | optional   | Any endpoint accepting a JSON POST. Unset, messages are logged instead |
| `CONTACT_RATE_LIMIT`   | optional   | Requests per minute per IP for `/api/contact` (default 5)              |

No secrets live in the repository. The contact endpoint degrades to structured
logging rather than failing when no webhook is configured.

## Decisions worth knowing

**Everything is static except one route.** The only dynamic handler is
`/api/contact`. Content pages are prerendered at build time, so the site is
fully crawlable without executing JavaScript.

**The cursor ring is additive, never a replacement.** A hairline ring trails the
pointer and opens into a faint halo over interactive elements. The native cursor
stays visible on purpose — hiding it is the fashionable choice and a bad one,
since any error in that component leaves a visitor with no pointer at all. It
renders only for fine pointers, never under `prefers-reduced-motion`, and not
until the pointer has moved. The ring is code-split behind a tiny gate and
mounted on an idle callback: mounting it directly cost ~3 mobile Lighthouse
points and 0.4s of LCP for a thing a phone can never display.
`pointer-events: none` on it is load-bearing and has a test.

**Motion never hides readable text.** Scroll reveals fade in below the fold,
where nothing is waiting to be read. Above the fold, and on route enter, the
entrance is CSS `transform`-only (`Rise`, `PageTransition`): an `opacity: 0`
element does not count as painted, so fading in server-rendered content delays
LCP and hides text until hydration. This also keeps the automated contrast
checks honest — three separate accessibility failures in this repo traced back
to that one mistake.

**The 3D is gated, not decorative-by-default.** The hero lattice is generated by
a pure function (`lib/lattice.ts`) shared by two renderers: a server-rendered
SVG that paints with the document, and a WebGL scene that cross-fades over it.
The WebGL path requires a `lg` viewport, a fine pointer, an idle main thread, an
on-screen canvas and a visible tab; it parks its render loop otherwise and runs a
single static frame under `prefers-reduced-motion`. three.js is never fetched on
mobile.

**Contrast is enforced, not eyeballed.** `scripts/check-contrast.mjs` parses the
oklch tokens out of `app/globals.css`, converts them to sRGB and asserts every
text colour clears 4.5:1 against both surfaces. The text ramp is compressed
because of that floor — hierarchy is carried by size, weight and spacing.

**The architecture diagram is HTML over SVG.** Edges are SVG; nodes are real
`<button>` elements positioned over them. That gives focus, labels and keyboard
operation for free rather than re-implementing them on SVG shapes.

**CSP keeps `'unsafe-inline'` for scripts, deliberately.** Next streams the RSC
payload through inline `<script>` tags. The alternative is a per-request nonce
from middleware, which forces every page out of static generation — a bad trade
for a site whose value is being static and instant. Every other directive is
strict and there is no user-generated content on the page.

## Measured results

Lighthouse against a production build (`next start`):

|         | Performance | Accessibility | Best practices | SEO |
| ------- | ----------- | ------------- | -------------- | --- |
| Desktop | 100         | 100           | 96             | 100 |
| Mobile  | 95–96       | 100           | 96             | 100 |

CLS 0 and TBT ≤ 30ms on both. Best practices is capped at 96 by the CSP
trade-off above. 55 Playwright tests cover accessibility (axe, WCAG 2.2 AA, on
five routes plus dark mode and the diagram's selected state), SEO surfaces,
security headers, the contact endpoint, the cursor ring and responsive
behaviour.
